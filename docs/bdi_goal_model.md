# BDI Goal Model

This document introduces the first BDI model for the CI/CD research prototype.

The model is implemented in:

```text
bdi/cicd_agent.asl
```

Scenario-specific beliefs are generated by Phase 3 and stored in:

```text
telemetry/generated_beliefs/
```

The runner combines one belief file with the agent template:

```text
bdi/run_agent_for_scenario.sh
```

## Root Goals

| Goal | Purpose | Context |
| --- | --- | --- |
| `!deliver_release` | Main release workflow | Always started by the first agent |
| `!maintain_reliability` | Check whether production is acceptable after deployment | Runs after production verification |
| `!recover_if_failed` | Choose recovery action when production is unstable or deployment fails | Triggered by failed production deployment, failed production health, or unstable environment |
| `!record_experiment_result` | Record that the reasoning trace completed | Symbolic in Phase 4 |

## Hierarchical Goal Decomposition

```text
!deliver_release
  -> !prepare_candidate
  -> !validate_candidate
  -> !deploy_to_staging
  -> !verify_staging
  -> !deploy_to_production
  -> !verify_production
  -> !maintain_reliability
  -> !record_experiment_result
```

Supporting recovery decomposition:

```text
!maintain_reliability
  -> !recover_if_failed when production is unstable

!recover_if_failed
  -> pause and reobserve when evidence is uncertain
  -> rollback production when production is unstable and rollback is available
  -> request manual intervention when rollback is not available
```

## Subgoals And Context Conditions

| Subgoal | Success Context | Failure Context | Action Or Decision |
| --- | --- | --- | --- |
| `!prepare_candidate` | `status(build, passed)` | `status(build, failed)` | Build or stop release |
| `!validate_candidate` | `status(test, passed)` and `status(security_scan, passed)` | `status(test, failed)` or `status(security_scan, failed)` | Test/security scan or stop release |
| `!deploy_to_staging` | `status(deploy(staging), passed)` | `status(deploy(staging), failed)` | Deploy staging or stop release |
| `!verify_staging` | `status(health_check(staging), passed)` and `environment(staging, stable)` | `status(health_check(staging), failed)` | Verify staging or stop release |
| `!deploy_to_production` | `status(deploy(production), passed)` | `status(deploy(production), failed)` | Deploy production or recover |
| `!verify_production` | `status(health_check(production), passed)` | `status(health_check(production), failed)` | Verify production or leave recovery to reliability goal |
| `!maintain_reliability` | `environment(production, stable)` | `environment(production, unstable)` | Complete release or recover |
| `!recover_if_failed` | `network_issue_suspected(true)` | None | Pause and reobserve |
| `!recover_if_failed` | `reobserve_after_failure(true)` | None | Pause and reobserve |
| `!recover_if_failed` | `environment(production, unstable)` and `rollback_available(production)` | None | Rollback production |

## Action Vocabulary

The first agent models these CI/CD actions:

```text
build(candidate)
test(candidate)
security_scan(candidate)
deploy(staging, candidate)
health_check(staging)
deploy(production, candidate)
health_check(production)
rollback(production)
pause(reason)
reobserve(production)
```

In Phase 4, these are represented as Jason trace output. Later phases may connect selected actions back to shell scripts or experiment result writers.

## Expected Scenario Decisions

| Scenario | Key Beliefs | Expected Agent Decision |
| --- | --- | --- |
| `success_stable` | `environment(production, stable)` and production health passed | `release_complete` |
| `production_unstable` | `environment(production, unstable)`, production health failed, rollback available | `rollback_production` |
| `stage_failure` | `status(test, failed)` | `stop_pipeline` |
| `rollback_midway_recovery` | Production unstable and `reobserve_after_failure(true)` | `pause_reobserve` |
| `network_issue_suspected` | Production unstable and `network_issue_suspected(true)` | `pause_reobserve` |

## Scope

This phase implements one explainable BDI agent. It does not add multi-agent coordination, ML, real monitoring, or production infrastructure.
